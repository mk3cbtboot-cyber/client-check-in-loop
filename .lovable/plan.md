# Grandfathered tier transitions (#19)

Principle: the practitioner tier gates what can be **created**, never what can be **seen or managed**. No client records are written, no migration is added.

## (a) Files and functions to change

**src/lib/tiers.ts** — add creation-scoped helpers, keep existing ones for creation gating only:
- `tierCanCreateMb(tier)` / `tierCanCreateCustom(tier)` (aliases of current `tierShowsMb` / `tierShowsCustom`, renamed at the call sites that gate creation).
- `tierAllowsType(tier, type)`.
- `tierTransitionWarning(next, counts)` — returns the count-aware confirmation copy, or null when nothing is being restricted.

**src/pages/Dashboard.tsx**
1. *Bootstrap* (~line 344-351): delete the two `setTypeFilter("mb" | "custom")` pins. The filter always starts at `all`.
2. *Filter tabs* (~1399): replace `tierShowsCustom(tier) && tierShowsMb(tier)` with a derived `hasMb || hasCustom` rule — render the tab group when the practitioner actually has both types, or has one type the current tier does not cover (so the "other" bucket stays reachable). Single-type + tier-matching practitioners still see no tabs.
3. *Per-client MB/Custom toggle* (~1657): currently `tierShowsToggle(tier)` (hybrid only). New rule: render the toggle when the client's current type is switchable, i.e. the *target* type is allowed by the tier. Under `custom_rx` an MB client shows its type as a read-only "MB" badge (fully editable plan, no conversion option); a custom client shows no MB option. Mirror for `metabolic_rx`.
4. *New-client dialog* (~1424, `newClientType`): only offer types the tier allows; if exactly one is allowed, preselect it and skip the chooser. Submission path (~681-702) validates `tierAllowsType`.
5. *Recipe Library button* (~1088) and the Macros/MPG tab (~1867, 1871, 2249): re-scope from "tier shows custom" to "this client is custom" — these are management surfaces for an existing custom client, so an existing custom client under `metabolic_rx` keeps them.
6. *Stats cards / list filters* (~1265-1341, 1562, 1593): unchanged logic, they already key off `typeFilter`; they simply stop being pinned.
7. *`saveTier`*: becomes two steps — compute counts, and if the target tier drops a type the practitioner still has clients of, open a new confirmation `AlertDialog` (modelled on the per-client toggle confirm) before writing `profiles.practitioner_tier`. Nothing else is written.

## (b) Determining the types the practitioner actually has

Derived in-memory from the already-loaded `clients` array — no new query:

```text
hasMb     = clients.some(c => c.client_type !== "custom")
hasCustom = clients.some(c => c.client_type === "custom")
```

Counts for the confirmation use the same array (active + archived, since archived clients are still managed). The dashboard already loads all of the practitioner's clients, so this stays reactive after add/archive/convert.

## (c) Every tier-gated spot, re-scoped

| Location | Today | After |
| --- | --- | --- |
| Bootstrap `setTypeFilter` pin | tier pins filter | removed |
| MB/Custom filter tabs | tier has both | practitioner has both (or has an off-tier type) |
| Per-client MB/Custom toggle | hybrid tier only | shown when the target type is creatable under the tier |
| New-client type chooser | implicit | explicit: only tier-allowed types |
| Recipe Library button | `tierShowsCustom` | client-scoped: any custom client exists / is open |
| Macros + MPG tab | `tierShowsCustom` && custom && generated | custom && generated (client-scoped) |
| Plan Format selector | tier | client-scoped, unchanged for existing clients |

Confirmed: **no writes to `clients`**, **no SQL migration**, **no edge-function change**. The only write is the existing `profiles.practitioner_tier` update, now behind a confirmation.

## (d) Edge cases

- **Single-type practitioner matching their tier** — no filter tabs, no toggle, no confirmation on tier change if the dropped type has zero clients. Identical to today.
- **`practitioner_rx` (hybrid)** — both types creatable, both tabs, toggle both ways: behaviour unchanged.
- **`metabolic_rx` <-> `custom_rx` direct switch** — symmetric. Existing clients of the dropped type stay listed, filterable, and editable; only creation and conversion into that type disappear. Switching back restores everything with no data touched.
- **Archived clients** counted in the warning so the numbers match what the practitioner can still restore.

## (e) Client portal

Untouched. `ClientPortal.tsx` and the client-facing edge functions never read `practitioner_tier`; all changes are inside the practitioner dashboard and `src/lib/tiers.ts`.

## Technical notes

- Filter state stays `"all" | "mb" | "custom"` — no schema or type changes.
- Confirmation dialog reuses the existing `AlertDialog` pattern already used by the per-client toggle, with wording generated by `tierTransitionWarning`, e.g. "Switching to Custom Rx. You have 15 MB clients; they stay fully accessible and editable, but you will not be able to create new MB clients. No data is deleted."
- `tierShowsToggle` is retired in favour of the per-direction check.
